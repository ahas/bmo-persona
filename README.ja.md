# bmo-persona

チャットエージェントのペルソナレイヤーとロア(lore)ライブラリを、ファイルとして保管します。ベースレイヤーは
エージェントのシステムプロンプトに含まれるペルソナで、トーンレイヤーとルームレイヤーはルームごとにその上へ重ねられ
ます。ロアライブラリは、参考資料としてエージェントに提示されるチャンクの索引です。レイヤー内の個人的な値は
プレースホルダーで、デプロイ側が自身の設定から埋めます。このリポジトリはサービスを動かしません。チェックは内容を
読み手が前提とする形式に保ち、デプロイは内容を読み手が探す場所に配置し、インストーラーはそれをチャット
エージェントのブレイン用のブレインファイルとして書き出します。

## 構成

| フォルダー | 内容 |
|---|---|
| `layers/` | ベースレイヤー、トーンレイヤー、そして `rooms/` 配下のルームレイヤー |
| `lore/` | ロアの索引、`chunks/` 配下のチャンク、チャンクの切り出し元となるソース文書 |
| `src/` | インストーラー:`docs/format.md` のとおりに内容を読み、ブレインファイルとして書き出す |
| `tests/` | 内容を形式に、リポジトリを規則に保つチェックと、インストーラーのテスト |
| `docs/` | 形式、境界、一覧についての正式なドキュメント |

ルートには、インストーラーとチェックの Cargo マニフェスト、バージョン、韓国語台帳(ledger)を伴う `testbed.toml`、
`rustfmt.toml`、MIT の `LICENSE`、`CLAUDE.md` があります。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/format.md` | レイヤーとそのトーン行の形、ロアの索引とチャンク、プレースホルダー |
| `docs/boundary.md` | リポジトリが提供するもの、デプロイによる配置方法、インストーラーが書き出すブレインファイル、どのユニットが何を受け取るか、ソースツリーの各読み手がどこへ行くか |
| `docs/inventory.md` | すべての内容ファイルの出典とパス、除外したもの、個人的な値を置き換えたすべてのプレースホルダー |
| `docs/PERSONAL-DATA.md` | リポジトリに決して入らない値、許可される二つの値、それを守るチェック |

## バージョン

- **リポジトリ全体で一つのバージョン**を semver で管理します。`VERSION` がそれを保持し、パッケージのバージョンは
  それと等しくなります。
- **変更によってバージョンがどう動くか**は、`docs/boundary.md` の「What this repository is」に記載されています。

## コマンド

```sh
cargo check --all-targets
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo run --bin bmo-persona-install -- --out <file>
```

最後のコマンドはブレインファイルを書き出します(`docs/boundary.md`、「The brain file」)。それをブレインに注入するのは
運用者の作業です。
